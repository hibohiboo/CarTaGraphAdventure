# ロードマップ

プロダクトのゴールと、そこへ向かうマイルストーンの**定義**だけを置く。マイルストーンの進み具合は、要望（`docs/backlog/`）の各ファイルに書いた「どのマイルストーンか」と状態から計算する（ダッシュボードは foundation で持ち込む）。決めた理由と、作らないことにしたものは[デザイナーノート](notes/roadmap.md)にある。

## ゴール

プレイヤーが遊びながら出した提案で、シナリオと機能が育っていくカードTRPGを作る。

最初はプレイヤー1人で遊べる土台だけを作る。GM・セッション・複数のプレイヤー・シナリオ製作の画面は、提案から必要になってから作る。

どのビートでも、プレイヤーは手札を出すか GM へ提案するかを選ぶ（[遊びの共通の形](cartagraph/index.md)）。提案は要望のファイル（`docs/backlog/`）になり、そこからシナリオと機能を育てる。

## マイルストーンの id と順番

- **id** — 中身を表す英語の短い名前。一度決めたら変えない。要望ファイルの `milestone` は id で書く
- **順番** — frontmatter の `milestones` の並び順だけで表す。未完了の要望が残る最初のマイルストーンを「いま取り組んでいる」とする

## マイルストーン

### foundation

開発と進化を動かす骨がある。

**完成の条件**

1. pnpm workspace・VitePress・Vitest・Biome・CI が動く
2. git フック（id 付きのブランチ・pre-commit・commit-msg の進化ログ・pre-push）が動く
3. `AGENTS.md`・`CLAUDE.md`・`docs/process/`（開発サイクル・grilling・tdd・レビュー）がある
4. 要望とダッシュボード、進化ログがある
5. DDD の文書（業務領域・集約・ユースケース）の枠と、要望からユースケース・画面・テスト・集約・イベントへのトレースがある
6. API ドキュメント（`packages/schemas` の API の一覧から作る OpenAPI の文書と Redoc の HTML）が Pages に載る
7. 開発の速さの足を引っ張る検査は持ち込まない。何を持ち込み、何を置いていくかは foundation のプランに書く

### core-loop

1シーンの遊びがテストで動く。

**完成の条件**

1. シーン・手札・カードを出す・提案するを、`packages/domain` の純粋な関数で表す
2. 遊んだことはイベントの列として残る。列を流し直すと同じ状態になる
3. 冒険者登録の試験の最初のシーンを、シナリオの JSON で表せる

### playable-scene

冒険者登録の試験の最初のシーンが遊べる。

**完成の条件**

1. ブラウザで試験の最初のシーンに入り、手札を出して次へ進める
2. 「GM へ提案する」で書いた文章が、開発サーバーから `docs/backlog/` の要望のファイルになる。ファイルには、シナリオとシーン、そこまでのイベントの列が入る
3. 提案の要望が完了か見送りになるまで、そのビートは「提案待ち」で止まる
4. 公開版（GitHub Pages）でも遊べる。提案の保存は開発サーバーのときだけ

### proposal-loop

提案からシナリオと機能が育つ。

**完成の条件**

1. 提案の要望を受け取って、シナリオの追加か機能の追加かを振り分け、開発サイクルで実装する手順が `docs/process/` にある
2. 要望を完了にすると、提案のファイルのイベントの列から、そのビートの続きを遊べる
3. 試験のシーンが、提案から増えている
