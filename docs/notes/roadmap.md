# ロードマップ（デザイナーノート）

[ロードマップ](../roadmap.md)の決めた理由と経緯。正式な定義はロードマップのページにある。

## 始めた理由（2026-10-30）

前のリポジトリ（CarTaGraphFantasy）では、GM・セッション・プレイヤー・シナリオ製作を一度に、つじつまを合わせて作ろうとして疲れてしまった。開発と進化を動かす仕組みはそこでかなりでき上がったので、その仕組みを持ち込み、作るものはプレイヤーとして遊べる土台から始め直す。

## キックオフで決めたこと（2026-10-30）

| 論点 | 決めたこと | ほかの案 |
|---|---|---|
| 提案の保存先 | 開発サーバーの口から `docs/backlog/` の要望ファイルに書く。前のリポジトリの、開発サーバーからシナリオの JSON を書く口と同じ形 | GitHub Issue（公開版からも保存できるが、認証と backlog への移し替えの手間が要る）、ダウンロードして手で置く |
| 提案した後のゲームの進み方 | そのシーンで止め、提案が実装されるまで先へ進めない | 記録だけして用意したカードの結果で進む、プレイヤーが自分で採否を決める |
| 前のリポジトリから持ち込むもの | DDD と RDRA のトレースはすべて持ち込み、アイデアから実装までの進み具合を追えるようにする。骨と、開発や進化を動かす部分もすべて持ち込む。開発の速さの足を引っ張る検査は置いていき、要るとわかったら足す | 骨だけ、ほぼ全部、ほぼ一から |

| MSW | 置いていく。API を叩かないうちは、シナリオの JSON を静的に読み込み、書き込みは開発サーバーの口だけにする | 最初から持ち込む（将来のバックエンドに備えられるが、使わないうちは重い） |
| API ドキュメント | 確かめていきたいので持ち込む。API ドキュメントは `packages/schemas` の API の一覧から作るので、`packages/schemas` は一覧と OpenAPI の組み立ての仕組みだけを持ち込む。最初の API は、提案を要望のファイルに書く開発サーバーの口 | API ができるまで置いていく（いったんはこちらに決めたが、同じ日に人間が持ち込むことにした） |
| キャラクターの作り方 | まず名前だけ。能力値などは、提案から要るとわかってから足す | 試験の最初のシーンを登録用紙（キャラクター作成）にする、あらかじめ作ったキャラクターで始める |

提案でシーンを止めるので、止めたシーンから続きを遊べることが要る。そこで遊んだことをイベントの列として持ち、提案のファイルにその列を入れて、列を流し直して再開する。止めるかどうかは要望ファイルの状態から決め、人が止めを外す作業をしなくて済むようにする。

## 進め方の構え

リスクを許して、まず進める。問題が出てから検査を足す。

## 今は作らないもの

- GM の画面・セッション・募集
- 複数のプレイヤー
- シナリオ製作の画面（シナリオは JSON を直してコミットする）
- バックエンド

どれも、提案から必要になったら要望にして作る。
