# 遊びの共通の形（デザイナーノート）

[遊びの共通の形](../cartagraph/index.md)の決めた理由と経緯。正式な定義は仕様のページにある。

## 名前を書くカード（2026-10-31）

キャラクターの名前は、試験の受付のシーンで手札「名乗る」を出すときに書く。名前を書く専用のシーン（登録画面）は作らなかった。どのビートでも「手札を出すか、GM へ提案するか」の2つのどちらかをする、という形を崩さないため。名前を書くことも、カードを出すことの一つにした。

採らなかった案：シーンの前の登録画面で名前を書く。試験の最初のシーンを丸ごと登録用紙（キャラクター作成）にする（[ロードマップのノート](roadmap.md)「キックオフで決めたこと」のほかの案）。

## 遊びの組み立ての構想（2026-10-31）

デジタル TRPG・ゲームブックとして、遊びを次のように組み立てる構想。いまのデータ（シナリオ・シーン・ビート）と画面は、この一部だけを作っている。

- キャンペーン：パーティーが何回もセッションを行い、キャラクターが育つ
- セッション：1つの冒険。オープニング・ミドル・クライマックス・エンディングのフェイズを持つ
- シーン：目的が1つ・場所が1つが基本。PC ごとのオープニングと、合同のオープニングがある。戦闘は独立したシーン
- ビート：シーンの中の、手札を1枚出すまでの一区切り（提案はその間に何度でもできる）。会話・判定・カードの獲得などが起きる

データの「シナリオ」は1つのセッションの台本にあたる。キャンペーン・セッション・フェイズ、シーンの目的・場所は、データにも画面にも持たせていない（要るシナリオを作るときに足す）。

## シーンとビートに分けた理由（2026-10-31）

会話の画面（P5）を作るときに、「シーン」の意味を決め直した。用語集の「シーン」は物語の1つの場面なので、そのまま残し、その中に「ビート」（プレイヤーが1回選ぶまでの一区切り）を並べた。会話が何往復も続くときは、会話のビートが続けて並ぶ。

採らなかった案：シーンを「選ぶところ1回」に定義し直す（用語集の定義が変わり、場面の意味で使う他のページとぶつかる）。「会話イベント」という単位を作る（ドメインイベント・イベントの列と名前がぶつかる）。

## 提案の決まりと止め方を決めた理由（2026-10-31）

提案の保存（P6）で、提案まわりの決まりを次のように決めた。

- **台詞を読み切ってから提案する** — 手札と同じ。読んでいる途中で提案できると、読んでいない台詞を前提にした提案が混ざり、要望から場面を再現しにくくなる。「いつでも」にはしなかった
- **文は前後の空白を除いて1〜4000文字（見た目の1文字）** — 名前（10文字）と同じ数え方。長い相談も書けるように大きくした。200文字・1000文字・上限なしも考えたが、短いと説明が書けず、上限なしだと要望のファイルが際限なく大きくなる
- **重ねて提案できる** — 提案待ちのビートでも、追加の提案ができる（別の要望ファイルになる。手札は出せないまま）。そのため、ビートの定義を「1回選ぶまで」から「手札を1枚出すまで」に直した。重ねて提案できないようにする案は、思いついたことを書き足せず、採らなかった
- **見送りでも止めを外す** — 要望を見送ったときに止めたままだと、そのビートで永久に遊べなくなる。「完了」だけを外す案は採らなかった
- **公開版では提案のカードを出さない** — 口は開発サーバーにしか無い。押せないカードを見せる案や、書いて文をコピーする案は、公開版の遊び手に何も起こらない操作を見せることになるので採らなかった。提案待ちの止めは、ビルド時の要望ファイルから効かせるので公開版でも効く
- **台詞を読んだ記録は、まだ残さない** — 提案したビートで読んだ台詞を要望のファイルに残すかは、未解決論点に残した。いまは手札を出した順と提案だけを残す
- **開発サーバーの口は LAN からも受け付ける** — スマホから提案できるように。送り元がループバックだけの案もあったが、遊びの確認はスマホで行うことが多い。そのぶん、同じ網の誰でも書ける（`Origin` が無い要求は通る）残るリスクは、`web-app.md` に書いた
- **MSW は使わない** — 最初の API を開発サーバーの口で受けるので、ブラウザでの偽のサーバーが要らない。依存も消した。画面のテストは送る関数を差し替える
- **口は Hono で書く** — 検査（送り元・Origin・本文の大きさ）を順に並べて書け、HTTP のサーバーを立てずにテストできるため。Node の `req`・`res` で自前に書く案は、本文を読み切る前に打ち切る処理などを自分で持つことになるので採らなかった

## プレイログを仮の形にした理由（2026-10-31）

会話の履歴（同じシーンで読んだ台詞）を出すには、遊んだことの並びが要る。本来はイベントの列（core-loop）で持つが、まだ決めていないので、`PlayState.log` に仮の形で持たせた。イベントの列を作るときに置き換える。リロードで消える点は P4 と同じ。（P6 で、手札を出した・提案したイベントの列を最小の形で作った。置き換えの対象は `PlayState.log` だけで、残りの未決は未解決論点にある）

## メモを別の要望にした理由（2026-10-31）

台詞の間に、自分のキャラクターが思ったことを書くメモは、将来の GM と PL のチャットにつながる。いまは対話の相手がいないので、思ったことをプレイログに残すところまでを別の要望（play-log-notes）にした。このサイクルでは、履歴を残す入れ物（プレイログ）までを作る。

## 名前の長さと数え方（2026-10-31）

- 上限は10文字。日本語として長い名前は、文の中で呼ばれたときに読みにくく不便なため。最初の案は20文字（仮）だった
- 文字は見た目の1文字で数える。コードポイントで数えると、結合文字（`e` + アクセント記号）は2、家族の絵文字は5、国旗は2と数え、見た目より多くなって、10文字に見える名前が断られるため
- ゼロ幅の文字・制御文字など、名前に入る文字の種類はまだ制限していない。困ることがわかったら決める
