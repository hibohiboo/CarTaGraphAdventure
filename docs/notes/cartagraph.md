# 遊びの共通の形（デザイナーノート）

[遊びの共通の形](../cartagraph/index.md)の決めた理由と経緯。正式な定義は仕様のページにある。

## 名前を書くカード（2026-10-31）

キャラクターの名前は、試験の受付のシーンで手札「名乗る」を出すときに書く。名前を書く専用のシーン（登録画面）は作らなかった。どのビートでも「手札を出すか、GM へ提案するか」の2つのどちらかをする、という形を崩さないため。名前を書くことも、カードを出すことの一つにした。

採らなかった案：シーンの前の登録画面で名前を書く。試験の最初のシーンを丸ごと登録用紙（キャラクター作成）にする（[ロードマップのノート](roadmap.md)「キックオフで決めたこと」のほかの案）。

## 遊びの組み立ての構想（2026-10-31）

デジタル TRPG・ゲームブックとして、遊びを次のように組み立てる構想。いまのデータ（シナリオ・シーン・ビート）と画面は、この一部だけを作っている。

- キャンペーン：パーティーが何回もセッションを行い、キャラクターが育つ
- セッション：1つの冒険。オープニング・ミドル・クライマックス・エンディングのフェイズを持つ
- シーン：目的が1つ・場所が1つが基本。PC ごとのオープニングと、合同のオープニングがある。戦闘は独立したシーン
- ビート：シーンの中の、プレイヤーが1回選ぶまでの一区切り。会話・判定・カードの獲得などが起きる

データの「シナリオ」は1つのセッションの台本にあたる。キャンペーン・セッション・フェイズ、シーンの目的・場所は、データにも画面にも持たせていない（要るシナリオを作るときに足す）。

## シーンとビートに分けた理由（2026-10-31）

会話の画面（P5）を作るときに、「シーン」の意味を決め直した。用語集の「シーン」は物語の1つの場面なので、そのまま残し、その中に「ビート」（プレイヤーが1回選ぶまでの一区切り）を並べた。会話が何往復も続くときは、会話のビートが続けて並ぶ。

採らなかった案：シーンを「選ぶところ1回」に定義し直す（用語集の定義が変わり、場面の意味で使う他のページとぶつかる）。「会話イベント」という単位を作る（ドメインイベント・イベントの列と名前がぶつかる）。

## プレイログを仮の形にした理由（2026-10-31）

会話の履歴（同じシーンで読んだ台詞）を出すには、遊んだことの並びが要る。本来はイベントの列（core-loop）で持つが、まだ決めていないので、`PlayState.log` に仮の形で持たせた。イベントの列を作るときに置き換える。リロードで消える点は P4 と同じ。

## メモを別の要望にした理由（2026-10-31）

台詞の間に、自分のキャラクターが思ったことを書くメモは、将来の GM と PL のチャットにつながる。いまは対話の相手がいないので、思ったことをプレイログに残すところまでを別の要望（play-log-notes）にした。このサイクルでは、履歴を残す入れ物（プレイログ）までを作る。

## 名前の長さと数え方（2026-10-31）

- 上限は10文字。日本語として長い名前は、文の中で呼ばれたときに読みにくく不便なため。最初の案は20文字（仮）だった
- 文字は見た目の1文字で数える。コードポイントで数えると、結合文字（`e` + アクセント記号）は2、家族の絵文字は5、国旗は2と数え、見た目より多くなって、10文字に見える名前が断られるため
- ゼロ幅の文字・制御文字など、名前に入る文字の種類はまだ制限していない。困ることがわかったら決める
