# テストレポート

main への push ごとに、デプロイ（`.github/workflows/deploy.yml`）がテストを流し、その結果の HTML レポートをこのサイトに載せる。テストが落ちてもデプロイは止めず、落ちたままのレポートを載せる（落ちたことはレポートと CI で気づく）。手元の `pnpm docs:dev` にはレポートが無いので、下のリンクは公開したサイトを開く。

| レポート | 中身 | 手元で流すコマンド |
|---|---|---|
| [E2E（Playwright）](https://hibohiboo.github.io/CarTaGraphAdventure/e2e-report/) | ビルドした画面をブラウザで操作するテスト。スクリーンショット付き | `pnpm web:e2e` |
| [ユースケースとの対応](https://hibohiboo.github.io/CarTaGraphAdventure/usecase-report/) | [中核のユースケース](use-cases.md)ごとの、E2E のテストと最新の結果。上の E2E のレポートの、そのテストへ飛べる | `pnpm web:e2e; pnpm usecase:report` |
| [トレース](https://hibohiboo.github.io/CarTaGraphAdventure/trace-report/) | 要望から、ユースケース・画面・ルールの節・テスト・集約・イベントまでのつながりを、層ごとの列に並べた図。押した要素の上流と下流がたどれ、要望ごとに届き具合が出る | `pnpm docs:build; pnpm web:e2e; pnpm test:report; pnpm trace:report`（`docs:build` が無いと、元の文書へのリンクがページまでになる） |
| [Vitest：Webアプリ](https://hibohiboo.github.io/CarTaGraphAdventure/vitest-report/web/) | `apps/web` のテスト（jsdom で全ページを描画） | `pnpm web:test` |
| [Vitest：ドメイン](https://hibohiboo.github.io/CarTaGraphAdventure/vitest-report/domain/) | `packages/domain` の純粋関数のテスト | `pnpm domain:test` |
| [Vitest：API のスキーマ](https://hibohiboo.github.io/CarTaGraphAdventure/vitest-report/schemas/) | `packages/schemas` のテスト | `pnpm schemas:test` |

## ユースケースとの対応の見方

ユースケースごとに、次のどれかの状態が出る。

| 状態 | 意味 |
|---|---|
| 確認済 | そのユースケースの正常パス（タグを付けたステップの主な流れ）を、E2E で確認した |
| 落ちた | ステップ（またはその外）で落ちた |
| 手前で止まった | 手前のステップで落ちたため、そのステップまで届かなかった（直す要望の注記の無いスキップを含む） |
| 全スキップ | そのユースケースを確かめるテストが全部、不安定なためスキップ中（直す要望の注記付き） |
| テストなし | そのユースケースのタグを持つ E2E が無い |
| 結果なし | E2E が起動できなかった等で、結果が読めなかった（ページの先頭に案内が出る） |

- 「確認済」は正常パスだけで、ユースケースのほかの流れ（断る・分かれる）までは確認していない。細かい分岐は Vitest が守る
- 1つのユースケースを複数のテスト・ステップが確かめるときは、落ちた ＞ 手前で止まった ＞ 確認済 ＞ 全スキップ の順で強いものを出す。一部のテストだけスキップなら、スキップでないテストの状態が出る
- 確かめるテストの一覧では、スキップしたテストに「スキップ中」と直す要望へのリンクが出る。直す要望の注記があっても、テストが通った・落ちたならその状態で出す（注記の消し忘れで落ちたのを隠さない）
- スキップ中のテストがあると、ページの先頭にその数と直す要望へのリンクが出る。スキップの書き方は[テストのルール](../process/rules/testing.md)の「不安定なテストのスキップ」
- ページはデプロイ時に作る（`scripts/build-usecase-report.mjs`）。E2E のテストへの ID の付け方・検査は[テストのルール](../process/rules/testing.md)の「ユースケースの E2E」

## ルールとの対応

ルールのページの節（`##`・`###`）ごとの結果のページは持ち込んでいない（[体制の進化ログ](../process/evolution/2026-10.md)）。節とテストのつながりは、下のトレースで見る。テストで確かめる性質でない節は[対象外の一覧](rule-test-exclusions.md)で宣言する。

## トレースの見方

アイデア（要望）が実装とテストまで届いているかを見るページ。左から、アクター・要望・ユースケース・画面とルールの節・テスト・集約・イベントの列に並べる。要素を押すと、その要素の祖先（左へ。なぜ作るか）と子孫（右へ。どこで確かめているか）だけが濃くなり、横のパネルに名前・状態・元の文書やテストのレポートへのリンクが出る。同じ要素か図の余白をもう一度押すと戻る。

つながりは書き写さず、既にある文書から組み立てる。要望の先頭（frontmatter）の `trace`（[要望の書き方](../backlog/index.md)）、[中核のユースケース](use-cases.md)の表のアクター・画面・集約・イベントの列、[画面一覧と導線](../screens/index.md)とルート定義、[集約とドメインイベント](aggregates.md)、ルールのページ、テストの結果。線の元（ユースケース・画面・節）から、それを確かめるテストのファイルへ線を引く（ユースケースは E2E のタグ、画面は smoke の題、節はルールのテストのタグ）。

| 状態 | 意味 |
|---|---|
| 確認済 | つなぐ先のテストが通った |
| テストなし | つなぐ先のテストが無い（スキップのみを含む） |
| 未実装 | 将来のユースケース、またはまだ無い画面 |
| 結果なし | E2E・Vitest が起動できなかった等で、結果が読めなかった |
| 全スキップ | ユースケースを確かめる E2E が全部、不安定なためスキップ中（ユースケースとの対応の見方と同じ。テストのファイルの要素も同じ） |
| 落ちた | つなぐ先のテストが落ちた（手前で止まったを含む） |
| つなぐ先なし | 開発の基盤など、要望の `trace` が `none` |
| 見送り | 要望の状態が見送り（届き具合を計算しない） |

- 要望の色（届き具合）は、つなぐ先の状態のうち、悪い順（落ちた ＞ 全スキップ ＞ 結果なし ＞ 未実装 ＞ テストなし ＞ 確認済）にいちばん悪いもの。つなぐ先のどれか1つでも確認済でなければ、要望は確認済にならない。全スキップは、ユースケースの段ではいちばん弱いが、要望の段では落ちたの次に悪い（理由は[前のリポジトリのデザイナーノート](https://github.com/hibohiboo/CarTaGraphFantasy/blob/main/docs/notes/architecture/test-report.md)）
- smoke と Vitest のスキップは、今どおり「テストなし」（smoke のスキップは検査が止める。ルールとの対応の見方では、Vitest のスキップは「スキップのみ」と出る）
- **未達** — 要望の状態が「完了」なのに、届き具合が確認済でないもの（全スキップを含む）。ページの先頭に件数と一覧が出る。つなぎ先の追加漏れか、テストの不足か、`trace` の書き間違いか、スキップしたままかを見る合図で、判定ではない
- 「確認済」は、つなぐ先のテストが通ったという意味にとどまり、要望の中身を全部確かめたという意味ではない。つなぎ方が正しいか（要望が実現したいことを、そのユースケース・画面・節で本当に確かめられるか）は、人間が `trace` の変更を見て確かめる
- 先頭の案内：結果が読めないもの（E2E・Vitest のパッケージ。Vitest が1つでも読めないときは、「テストなし」の節を「結果なし」に上げる）、収集で落ちたファイル（どの節のテストか分からないので状態に入れない）、当たらないルート（smoke の題の書き方が変わり、画面が黙って「テストなし」になるのを止める）、スキップ中のテストの数と直す要望へのリンク
- 枠の色は業務領域・コンテキスト。要素の中の文字（「落ちた」など）にも状態を出し、色だけに頼らない
- ページはデプロイ時に作る（`scripts/build-trace-report.mjs`）。`trace` と表の列の検査は `pnpm docs:build`（`scripts/check-trace.mjs`）。決めた理由は[前のリポジトリのデザイナーノート](https://github.com/hibohiboo/CarTaGraphFantasy/blob/main/docs/notes/architecture/test-report.md)

Vitest の HTML レポートを手元で作るときは `pnpm test:report`（各パッケージの `.vitest/` に HTML、`vitest-results/` に JSON を書く。git には載せない。Vitest 5 は HTML の出力先を指定できない）。レポートを dist に写す（`.vitest/` を Pages 上の `vitest-report/<パッケージ>/` に置く）のは `scripts/copy-test-reports-to-pages.mjs`。テストの書き方は[テストのルール](../process/rules/testing.md)。
