# 業務領域の分類

プロダクトの業務領域を、中核・補完・一般に分ける。どこに設計の手間をかけるかを決めるため。ドメイン駆動設計の戦略的設計にあたる。

## 分類の基準

| 分類 | 意味 | 手間のかけ方 |
|---|---|---|
| 中核 | このプロダクトならではの価値 | 自分たちで設計し、ドメインモデルを育てる |
| 補完 | 中核を支えるが、ほかと大きく変わらない | 単純に作る |
| 一般 | どこでも同じ | 外部のサービス・ライブラリに任せる |

## 業務領域の一覧

| 業務領域 | 分類 | 中身 |
|---|---|---|
| プレイ | 中核 | ビートで手札を出す・GM へ提案する（[遊びの共通の形](../cartagraph/index.md)） |
| 提案の取り込み | 中核 | 提案を要望として残し、シナリオと機能に育てる |

中身の集約・ユースケースは core-loop で決める（[ロードマップ](../roadmap.md)）。

## 見直しのきっかけ

- GM・セッション・複数のプレイヤーを作ると決めたとき
