# 実装パターン

コンテキストごとに、ドメインのロジックをどの形で実装するかを決める。

## パターンの意味

| パターン | 形 | 向くところ |
|---|---|---|
| イベント履歴式 | 起きたことの列を正とし、状態は列を流し直して作る | 遊んだことの記録・再開・リプレイが要るところ |
| ドメインモデル | 集約の状態を正とし、操作で新しい状態を返す | 状態だけが要るところ |
| 値オブジェクトと純粋関数 | 状態を持たない計算 | 判定・計算 |

## コンテキストごとの選択

| コンテキスト | パターン | 理由 |
|---|---|---|
| プレイ | イベント履歴式 | 提案したビートの続きから再開するため、遊んだことの列を要望のファイルに写す。状態は `replay` で列から作る（残りの未決は[未解決論点](../open-questions.md#次に詰める候補)） |

## イベントの種類

| イベント | 中身 |
|---|---|
| 手札を出した | `cardPlayed`：`beatId`・`cardId`。名前を書くカードのときだけ、正規化した後の `characterName` |
| GM へ提案した | `proposed`：`beatId`・正規化した後の提案の文 `text` |

## テストの形

- 純粋関数は入力と出力だけで確かめる（[テストのルール](../process/rules/testing.md)）
