# 依存の古さと脆弱性を月に1回知らせる

[依存の版を上げる](dependency-upgrade.md)（P3）の振り返りで、体制の進化の候補「依存の版が、気づかないうちに古くなる」を、案 a（CI の月1回の定期実行）で採用した（2026-10-31。[進化ログ](../process/evolution/2026-10.md)）。

- **やること** — `.github/workflows/` に月1回の定期実行（と手動実行）を足し、`pnpm outdated -r` と `pnpm audit` の結果を Issue に書く。Issue は1つにして、毎回書き換える（溜まり具合を1か所で見る）
- **採らなかった案** — Dependabot・Renovate で PR を自動で作る：P3 では版を上げるたびに設定やテストの直しが要り（Biome のルール・redocly のオプション・TypeScript の `baseUrl`・Vite のチャンク分け・Vitest の出力先）、自動の PR はそのままでは取り込めないことが多い。思い立ったときに要望を立てる：P1 のように差が溜まる
- **決めること（プランで）** — 何もなかった月に Issue をどうするか（閉じる・そのまま）、mermaid のように留めている依存の出し方
