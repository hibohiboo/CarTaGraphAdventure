# 未解決論点トラッカー

まだ決まっていない仕様と開発の仕組みを並べる。決めたら、決めたことを正式なページに書き、ここから消す（決めた理由はデザイナーノートへ）。

## 次に詰める候補

- **遊んだことの持ち方の残り** — 手札を出した・提案したことは、イベントの列で持つと決めた（[集約](architecture/aggregates.md)）。未決は、会話の履歴の入れ物が仮の形で `PlayState.log` にあること（イベントの列に置き換えるときの形）、提案したビートで読んだ台詞（手札を出していないのでイベントの列にも無い）を残すか、提案のファイルの列から続きをどう再開するか。core-loop と proposal-loop で決める（[ロードマップ](roadmap.md)）

## 仕様の細部の未決

- **キャラクターが持ち込む手札** — キャラクターはまず名前だけを持つ。持ち込むカードをいつ・どう持たせるか（[手札](glossary.md#手札)）。持ち込むカードを使うシナリオを作るときに決める
- **判定・カードの獲得をビートでどう表すか** — ビートの種類にするか、カードを出した結果として起こすか。使うシナリオを作るときに決める
- **キャラクターの口調** — 自分の台詞は、いまは名前だけ（カードの `say`）。性格による口調を、どうデータにして台詞に反映するか。名前以外の設定を持つキャラクターを作るときに決める
