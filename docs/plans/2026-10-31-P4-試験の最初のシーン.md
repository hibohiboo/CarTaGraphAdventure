# 試験の最初のシーン

- 要望：[試験の最初のシーンで名乗れる](../backlog/exam-first-scene.md)
- 状態：手順1（プラン作成）が済んだ。人間に確かめたことは「詳細設計」の「人間に確かめたこと」。次は手順2〜3（プランの AI レビュー・テスト網羅レビュー）を新しいセッションで、等級は強い（`opus`）

## 1. 概要

`pnpm web:dev` で開いたアプリのホームから冒険者登録の試験に入り、受付のシーンで手札「名乗る」を出して、キャラクターの名前を書けるようにする。名前を書くと次のシーンで試験官が名前を呼び、「続きは準備中」で止まる。

画面の中身はシナリオの JSON から描く。そのために、シーン・手札・キャラクターの名前の最小の型（zod）と純粋関数を `packages/domain` に作る。

## 2. 背景

- 人間の要望（2026-10-31）：「`npm run web:dev` でプレイできる環境を作ってください。キャラクターの名前を入力するところまで」
- ロードマップ（`docs/roadmap.md`）は core-loop（ドメインで1シーンの遊び）→ playable-scene（ブラウザで遊べる）の順。今回は人間の判断で、core-loop の一部（型・純粋関数・シナリオの JSON）を最小で作り、その上に画面を載せる。イベントの列（core-loop の完成の条件2）は作らない
- 正式仕様：[遊びの共通の形](../cartagraph/index.md)「シーンですること」「キャラクター」、用語集の「シーン」「手札」「キャラクター」「冒険者登録の試験」
- 未解決論点（`docs/open-questions.md`）
  - 「遊んだことの持ち方」（イベントの列）… 触れない。状態は画面のメモリだけに持ち、リロードで最初に戻る
  - 「公開版での提案」… 触れない。提案のボタンを今回は出さない（下の D6）
- デザイナーノート（`docs/notes/roadmap.md`「キックオフで決めたこと」）の「キャラクターの作り方」は「まず名前だけ」に決まっていて、ほかの案に「試験の最初のシーンを登録用紙（キャラクター作成）にする」がある。今回は、シーンの中で手札「名乗る」を出して名前を書く（人間が選んだ）。最初のシーンを丸ごと作成画面にする案とは別で、名前のほかは持たせない

## 3. 詳細設計

### 人間に確かめたこと（2026-10-31）

| 論点 | 決めたこと | ほかの案 |
|---|---|---|
| 範囲 | 最小のドメイン（型・純粋関数）とシナリオの JSON も作り、画面はそれを読んで描く | 画面だけ作り、文章は画面のコードに直書き |
| 名前を書く場所 | 受付のシーンで手札「名乗る」を出すと、名前の入力欄が出る | シーンの前の登録画面 |
| 名前を書いた後 | 次のシーンで試験官ミルダが名前を呼ぶ一文を出し、「続きは準備中です」で止まる | 入力欄までで止める |
| 手札 | 「名乗る」の1枚だけ。GM へ提案するボタンは出さない | ほかのカードを押せない形で並べる、押せて結果の文も出す |

### 決めたこと

- **D1 カードを出すときに名前を書く** — 「名乗る」は、出すときにキャラクターの名前を書くカード。名前の入力欄はカードを選んだときに出し、名前を確定すると、カードを出したことになって次のシーンへ進む。名前を書く専用のシーンは作らない（仕様の「シーンごとに、手札を出すか提案するか」のままにするため）
  - 仕様の追記（`docs/cartagraph/index.md`「シーンですること」）：「カードには、出すときにキャラクターの名前を書くものがある。名前を書いて出すと、キャラクターの名前になる」。理由は `docs/notes/cartagraph.md` を作って書く（`docs/notes/index.md` の置き場所）
- **D2 名前の決まり** — 前後の空白を取り除いてから、1〜20文字。空（空白だけ）と21文字以上は断り、入力欄の下に理由を出す。文字数は `Array.from` で数える（サロゲートペアを1文字に）。20 は仮の値（**人間に確かめること**。実装順の T0）
- **D3 シナリオの JSON の置き場所** — core-loop で決めることになっていた（`docs/process/rules/testing.md`「テストのデータ」、`docs/process/index.md`「適用範囲」）。`packages/domain/src/scenario/adventurer-exam.json` に置き、同じディレクトリの `adventurer-exam.ts` が zod で読んで（`parse`）書き出す。画面は `@cartagraph/domain/scenario/adventurer-exam` を import する（`package.json` の `exports` は `./*` → `./src/*.ts` なので、JSON を直接は指せない）。JSON の読み込みに `resolveJsonModule` が要るなら `packages/domain/tsconfig.json` に足す。置き場所は `docs/process/` の2か所の「core-loop で決める」を、この置き場所に書き換える
- **D4 ドメインの形**（`packages/domain/src/scenario/`。仕様のページは `docs/cartagraph/index.md`）
  - `model.ts`：`cardSchema`（`id`・`title`・`text`・`next`（次のシーンの id）・`asksCharacterName`（省略時 false））、`sceneSchema`（`id`・`title`・`text`（段落の配列）・`hand`（カードの配列。空なら続きは準備中））、`scenarioSchema`（`id`・`title`・`start`・`scenes`）、`playStateSchema`（`sceneId`・`characterName`（未定は null））
  - `transition.ts`：`startPlay(scenario)`、`playCard(scenario, state, cardId, characterName?)` → `{ ok: true, state }` か `{ ok: false, reason }`。断る理由は `unknownCard`（今のシーンの手札に無い）・`nameRequired`（名前が要るカードに名前が無い・空）・`nameTooLong`。`normalizeCharacterName(raw)` も同じファイル
  - `text.ts`：`renderText(text, state)` が `{characterName}` を名前に置き換える
  - `refs.ts`：`findBrokenRefs(scenario)` が、`start` とカードの `next` が指すシーンの無いものを返す（シナリオを手で直すので、テストで止める）
  - アーキテクチャルールの「ディレクトリと依存の向き」の表に `scenario` を足し、`biome.json` の domain の override にも足す。`src/index.ts`（殻）と `index.test.ts` を消す
  - 集約とイベントは決めない（`docs/architecture/aggregates.md` は触らない）
- **D5 画面** — ルート `/exam`（題名「試験のシーン」、グループ `pl`）を `routes.ts` と `app/router.tsx` に足す。ページは `pages/pl/exam/ui/ExamPage.tsx`。状態は `useState` の `PlayState` だけ。ホームの「まだ準備中です」を、`/exam` へのリンク「試験を受ける」に替える
  - シーンの題と段落（`renderText` を通す）を出し、手札をボタンで並べる。名前が要るカードを押すと、ラベル「キャラクターの名前」の入力欄と「この名前で名乗る」ボタンが出る。断られたら理由を `role="alert"` で出し、シーンは進めない
  - 手札が空のシーンでは「続きは準備中です。」を出す
- **D6 提案のボタンは出さない（仮）** — 仕様では、どのシーンでも GM へ提案できる。今回は提案の保存（playable-scene の別の要望）が無いので、ボタンを出さない。画面に「GM への提案は準備中です（仮）」と出す（`docs/process/index.md` の8項目の3「仮」）
- **D7 シナリオの中身** — チャットで演じた冒頭（2026-10-31）を元にする
  - `reception`「ギルドの受付」：扉を押し開け、試験官ミルダに登録用紙へ名前を書くよう言われ、「試験はもう始まっている」と告げられる。手札は「名乗る」（胸を張って、自分の名前を告げる。`asksCharacterName: true`、`next: exam-begins`）
  - `exam-begins`「試験の始まり」：「{characterName}さんね。では、試験を始めましょう」とミルダが用紙を受け取る。手札は空
- **D8 docs の追従** — `docs/screens/index.md`（導線図の点線を `/exam` に、表にパス）、`docs/architecture/use-cases.md`（PL-1 の画面を `` `/exam` ``）、要望の `trace.screens` を `/exam` に、`docs/architecture/known-issues.md` の「`screens: [/]` は PL-2 の画面と合っていない」の行（`docs/backlog/index.md` の例を `/exam` に直して消す）
- **D9 React の `useTopLevelRegex`** — アーキテクチャルール「React の書き方」の「最初に React のコードを書くときに決める」は、今回は正規表現を書かないので決めない（そのまま残す）

## 5. 新規テストケース

ドメイン（`packages/domain/src/scenario/*.test.ts`。仕様の節を確かめるものにだけ `rule:index/シーンですること` のタグ）

1. `adventurer-exam` が `scenarioSchema` を通り、`findBrokenRefs` が空
2. `findBrokenRefs`：`start` が無いシーンを指す・カードの `next` が無いシーンを指すと、それぞれ返す
3. `startPlay` は `start` のシーンで、名前は null
4. `playCard`：「名乗る」に名前を付けて出すと、`next` のシーンへ進み、名前が入る（タグ）
5. `playCard`：今のシーンの手札に無いカード（別のシーンのカード・無い id）は `unknownCard` で断り、状態を変えない（タグ）
6. `playCard`：名前が要るカードに名前が無い・空・空白だけは `nameRequired`
7. 名前の境界：前後の空白を取り除く、1文字と20文字は通る、21文字は `nameTooLong`、サロゲートペア（絵文字）20個は通る
8. `renderText`：`{characterName}` を名前に置き換える。名前が null なら置き換えずにそのまま残す（名前の無いうちに出す文に `{characterName}` を書かないのはシナリオの側の決まり）
9. 手札が空のシーン（`exam-begins`）では、どのカードも `unknownCard`

画面（`apps/web/src/test/examScene.test.tsx`）

10. ホームの「試験を受ける」から受付のシーンの題と、シナリオの段落が出る（文言はシナリオのデータから引く）
11. 「名乗る」→ 名前を書いて確定 → 次のシーンの題と「{名前}さんね」の文と「続きは準備中です。」が出る
12. 空白だけで確定すると理由が出て、受付のシーンのまま
13. 「GM への提案は準備中です（仮）」が出る

E2E（`apps/web/e2e/usecases/pl-1-play-card.test.ts`、タグ `@PL-1`）

14. ホームから入り、ステップ「PL-1 名乗るを出す」で名前を書いて次のシーンまで進む。最後に同じステップの中でコンソールの誤りが無いこと（人間が補えない進行を、画面から最後まで通す）
