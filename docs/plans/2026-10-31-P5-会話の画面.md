## 1. 概要

試験のシーンを、ミルダと話す場面だけ「会話の画面」で遊べるようにする。画面は上に NPC のカード（絵・名前・肩書）、真ん中にチャットのような会話、下に自分のキャラクターのカードと手札を並べる。会話は台詞を1つずつタップして読み進め、読み終えると手札が出る。手札を出すと自分の台詞も会話に足される。ギルドの扉を開けるところは今の紙面のまま。

そのために、シナリオに「紙面」と「会話」の2つの見せ方、NPC、台詞の行、絵（アイコンか画像）、カードの自分の台詞を足し、遊んだことの並び（プレイログ）を `PlayState` に仮の形で持たせる。

### 決めたこと

- **D1 シーンの見せ方**（`packages/domain/src/scenario/model.ts`）
  - `sceneSchema` を `layout` で分ける `z.discriminatedUnion`：
    - `layout: 'paper'`：`id`・`title`・`text`（段落の配列。P4 と同じ）・`hand`
    - `layout: 'conversation'`：`id`・`title`・`lines`（台詞の行の配列。1行以上。各行は `speaker`（NPC の id）と `text`）・`hand`
  - `layout` は省略できない（既定値を持たない。どちらの見せ方かをデータから必ず読めるようにする）。既存のシーンは `layout: 'paper'` を足す
  - `speaker` が指すのは `npcs` の id。参照の切れは `scenarioSchema` の `superRefine` で止める（P4 と同じ方針。読むすべての経路で止まる）。誤りの `path` は `scenes.1.lines.0.speaker` のように場所を指す
- **D2 NPC と絵**
  - `scenarioSchema` に `npcs`（配列）を足す。`npcSchema`：`id`・`name`・`title`（肩書）・`description`（ひとこと）・`portrait`
  - `portraitSchema` は `{ type: 'icon', name }` か `{ type: 'image', src }`。ドメインは React を知らないので `name` は文字列のまま。NPC の id の重複と、予約語 `player` を id にすることを `superRefine` で止める
  - 画面側（`apps/web/src/pages/pl/exam/ui/`）に `Portrait` を作る。`type: 'icon'` は `portraitIcons.ts`（`react-icons/gi` から使うものだけを import した、名前 → 部品の登録表）から引き、`type: 'image'` は `<img src alt={NPC の名前}>`。登録表に無い名前は `Portrait` が例外にする（シナリオの誤りを黙って隠さない。P4 の「シーンが見つからない」と同じ）。シナリオの NPC の `icon` の名前がすべて登録表にあることをテストで確かめる
  - 自分のカードの絵は、画面側の定数（共通のシルエットのアイコン）。ドメインのデータには持たせない
  - `react-icons` を `apps/web` の依存に足す。版は実装のセッションで、リリースから2週間以上経ったものを確かめて決める。アイコンの名前が実在することは `web:typecheck` が確かめる（`gi` から名前で import するため）
- **D3 台詞の送り（画面の状態）**
  - 会話のシーンに入ると、最初の台詞が出ている状態から始める（プランで置いた既定。会話エリアが空のまま「次へ」だけが出るのを避けるため。人間レビューで変えてよい）。「次へ」ボタンを押すたびに1つずつ出る。出し切ると「次へ」が消え、手札と「続きは準備中です。」（手札が空のとき）が出る。出し切るまで手札は出さない
  - 送り位置は `ExamPage` の `useState`（UI の状態）。シーンが変わるたびに最初に戻す（`key` で描き直す）
  - 会話エリアは `role="log"`（新しい台詞が読み上げられる）
  - 上の NPC カードは、そのシーンで直近に出た台詞の話し手を出す
- **D4 自分の台詞**：`cardSchema` に `say`（省略できる文字列）を足す。`{characterName}` は表示のときに置き換える（`renderText`）
- **D5 プレイログ（`PlayState.log`。仮の形）**
  - `logEntrySchema`：`sceneId`・`speaker`（NPC の id・`'player'`（定数 `PLAYER_SPEAKER`）・`null`（地の文））・`text`。`text` は `{characterName}` を置き換える前の形で持ち、表示のたびに置き換える（名前が決まった後も食い違わない）
  - `playStateSchema` に `log`（配列）を足す。`startPlay` は `[]`
  - `playCard` が、成功したときだけ、出したカードを出すシーンの内容をログの末尾に足す：紙面のシーンは各段落（`speaker: null`）、会話のシーンは各行（`speaker` は NPC の id）。続けて、カードに `say` があれば自分の台詞（`speaker: 'player'`）を足す。断った場合は `state` ごと返さないので、ログは増えない。入力の `state` は書き換えず、新しい `state` を返す（P4 と同じ）
  - ログに入るのは「出し切った台詞」だけ（手札が出るのは出し切った後なので、途中までの台詞をドメインは知らない）。いま遊んでいるシーンの台詞は、画面が送り位置まで描く
  - `conversationHistory(scenario, state)`（`packages/domain/src/scenario/log.ts`）：会話エリアに出す履歴を返す。ログの末尾から、`sceneId` が会話のシーンの行が続く間だけを遡って返す（紙面のシーンの行に当たったら止める）。境界を表すフィールドは持たない（`sceneId` からシナリオを引けば決まる）
  - イベントの列（core-loop）を作るときに、このログは置き換える。`docs/open-questions.md` の「遊んだことの持ち方」に「ログの形は仮」と1行書く
- **D6 画面の構成**（`ExamPage` を `layout` で分ける。`pages/pl/exam/ui/`）
  - 紙面のシーン：今の画面のまま（`PaperScene`）
  - 会話のシーン（`ConversationScene`）：
    - 上：`NpcCard`（絵・名前・肩書の横長の帯）。h1 はシーンの題のまま（どのシーンでも h1 はちょうど1つ）
    - 中：会話エリア。履歴（`conversationHistory`）の後に、いまのシーンの出た台詞を並べる。NPC の台詞は左、自分の台詞は右の吹き出し。残りの高さを占め、新しい行へ自動でスクロールする
    - 下：自分のカード（`PcCard`。名前か「（まだ名乗っていない）」と共通のシルエット）と手札。幅が狭いときは、自分のカードを手札の上の小さな帯にする
  - 名前の入力欄（`NameForm`）：会話エリアと手札の間に、今の登録用紙をそのまま出す。選んだときに記入欄へフォーカスを移す今の動きも残す
  - 提案の「準備中（仮）」：紙面・会話のどちらでも手札の隣
  - 見た目のトークンは P4 のデザインシステムのもの（`apps/web/src/app/styles/tokens.css`）。吹き出し・会話エリア・NPC の帯の役割は `docs/architecture/web-app.md`「デザインシステム」に足す
- **D7 シナリオの中身**（`adventurer-exam.json`。組み替えだけ）
  - `npcs`：ミルダ（`milda`。`name` は「ミルダ」、`title` は「試験官」、`description` は「ギルドの登録を受け持つ女性」、絵は `icon`）
  - `entrance`「ギルドの扉」（紙面）：段落は「重い扉を押し開けると、酒と油の匂いがした。冒険者ギルドの受付には、書類の束を前にした女性がひとり座っている。」。手札は新しいカード「受付へ進む」（`next: reception`、名前は書かない）。`start` は `entrance`

## 5. 新規テストケース

ドメイン（`packages/domain/src/scenario/*.test.ts`。仕様の節「シーンの見せ方」を確かめるものに `rule:index/シーンの見せ方`、手札を出す・名前の決まりは P4 のタグのまま）

1. `adventurer-exam` が `scenarioSchema` を通る。`start` から全シーンに辿り着ける。名前を書くカードを通らずに辿り着けるシーンの文（紙面の段落・会話の台詞・`say`）に `{characterName}` が無く、名前の後のシーンの文にはある。会話のシーンは台詞を1つ以上持ち、すべての `speaker` が `npcs` にある
2. `scenarioSchema` の参照の検査（実データを1か所だけ書き換える）：`speaker` が無い NPC を指す、NPC の id の重複、NPC の id が `player`、会話のシーンの `lines` が空、`portrait` の `type` が未知、`type: 'image'` に `src` が無い、は `safeParse` が失敗し、`path` がその場所を指す。書き換えない実データは通る（両側）。P4 の参照の検査（`start`・`next`・id の重複）は変えずに通る
3. `portraitSchema`：`icon`（`name` あり）と `image`（`src` あり）を通し、`type` が無い・混ざった形は断る
4. `startPlay`：`log` は空

## 8. スコープ外

- 台詞の間に自分のキャラクターが思ったことを書くメモ（別の要望 [play-log-notes](../backlog/play-log-notes.md)。このサイクルのログ `log` に「メモ」の種類を足す形で作る）
- 「章」の単位をデータに持つこと（宿のオープニングを書くときに決める）
- GM と PL のチャット（いまは対話の相手がいない。ノートに書くだけ）
- 手札のカードの絵・カードの絵柄の画像素材（`image` の型は作るが、実データはアイコンだけ）
- 台詞のタイプ演出・自動送り・送り位置を残して続きから遊ぶこと（続きから遊べる仕組みは未解決論点「遊んだことの持ち方」）
- 会話のシナリオに新しい台詞・新しいカードを足すこと（導線のカード「受付へ進む」と `say` の1行を除く）
- プレイログの保存（リロードで消える。P4 と同じ）
- 名前の入力欄のチャット風の入力欄（人間レビューで要望が出たら）
- 提案のボタンと保存（playable-scene の別の要望）
