# 会話の画面

- 要望：[NPC と会話する場面を、会話の画面で遊べる](../backlog/conversation-mode.md)（同じ人間の要望から、メモは別の要望 [play-log-notes](../backlog/play-log-notes.md) に分けた）
- 状態：手順1〜3（プラン作成・プランの AI レビュー・テスト網羅レビュー）が済み、1回目の P0 は反映した。その後、人間の判断で「シーン＝場面、その中にビート」に組み直した（「人間に確かめたこと」の後半）。組み直したところを3観点で再レビューする。済んだら新しいセッションで手順4〜5（実装とテスト）、等級は標準（`sonnet`）

## 1. 概要

試験の受付で、ミルダと話すところを「会話の画面」で遊べるようにする。画面は上に NPC のカード（絵・名前・肩書）、真ん中にチャットのような会話、下に自分のキャラクターのカードと手札を並べる。会話は台詞を1つずつタップして読み進め、読み終えると手札が出る。手札を出すと自分の台詞も会話に足される。ギルドの扉を開けるところは今の紙面のまま。

そのために、シナリオの形を「シーン（場面）の中にビート（プレイヤーが1回選ぶまでの一区切り）が並ぶ」に組み直し、ビートに「紙面」と「会話」の2つの見せ方、NPC、台詞の行、絵（アイコンか画像）、カードの自分の台詞を足す。遊んだことの並び（プレイログ）を `PlayState` に仮の形で持たせる。

### 決めたこと

- **D1 シーンとビート**（`packages/domain/src/scenario/model.ts`）
  - `sceneSchema`：`id`・`title`・`beats`（ビートの配列。1つ以上）
  - `beatSchema` は `layout` で分ける `z.discriminatedUnion`（それぞれ `z.strictObject`）：
    - `layout: 'paper'`：`id`・`text`（段落の配列。P4 の `text`）・`hand`
    - `layout: 'conversation'`：`id`・`lines`（台詞の行の配列。1行以上。各行は `speaker`（NPC の id）と `text`）・`hand`
  - P4 の `Scene`（題・段落・手札を持つもの）は、題をシーンに残し、段落と手札をビートへ移す。`layout` は省略できない（既定値を持たない）
  - `scenarioSchema`：`id`・`title`・`start`（ビートの id）・`npcs`・`scenes`。`superRefine` で止めるもの：ビートの id の重複（シナリオ全体で）、シーンの id の重複、`start` とカードの `next` が無いビートを指す、同じ手札の中のカードの id の重複（P4 から）、NPC の id の重複・`player`、`speaker` が無い NPC を指す。誤りの `path` は場所を指す（`scenes.0.beats.1.lines.0.speaker` など）
  - zod 4.6.7 の挙動（node_modules で確かめた）：`discriminatedUnion` は判別の値が合わないと `path` に判別のキーを付ける（`layout` が無い・未知なら `scenes.0.beats.0.layout`）。形の誤りが1件でもあると `superRefine` は走らない（形の誤りと参照の誤りを同時には報告しない）。余分なキーは `z.strictObject` で断る（`layout: 'paper'` に `lines` を入れるなど）
  - `locateBeat(scenario, beatId)`（`transition.ts`）：ビートと、それが属するシーンを返す（無ければ `undefined`）。画面と `conversationHistory` が使う
- **D2 NPC と絵**
  - `npcSchema`：`id`（1文字以上）・`name`・`title`（肩書）・`description`（ひとこと。`NpcCard` が名前・肩書の下に小さく出す。幅が狭いときは隠す）・`portrait`
  - `portraitSchema` は `{ type: 'icon', name }` か `{ type: 'image', src }`（それぞれ `z.strictObject`。`name`・`src` は1文字以上）。ドメインは React を知らないので `name` は文字列のまま。会話の行の `speaker` に `player` は書けない（`npcs` に無いので参照の切れになる。自分の台詞は `say` だけで表す）
  - 画面側（`apps/web/src/pages/pl/exam/ui/`）に `Portrait` を作る。`type: 'icon'` は `portraitIcons.ts`（`react-icons/gi` から使うものだけを import した、名前 → 部品のオブジェクトの表。`export { … } from` は `noBarrelFile`・`noReExportAll` に当たるので使わない）から引き、`type: 'image'` は `<img src alt={NPC の名前}>`。登録表に無い名前は `Portrait` が例外にする（シナリオの誤りを黙って隠さない。P4 の「シーンが見つからない」と同じ）
  - 自分のカードの絵は、画面側の定数（共通のシルエットのアイコン）。ドメインのデータには持たせない
  - `react-icons` を `apps/web` の依存に足す。版は実装のセッションで、リリースから2週間以上経ったものを確かめて決める。アイコンの名前が実在することは `web:typecheck` が確かめる。`biome.json` の `noRestrictedImports` は `react-icons` を止めないことを確かめた。`gi` は全アイコンが1つのモジュールにあるので、導入のときに `pnpm build:pages` などのビルドで、使う名前だけが入っていること（ビルドの大きさ）を確かめる
- **D3 台詞の送り（画面の状態）**
  - 会話のビートに入ると、最初の台詞が出ている状態から始める（AI の既定。会話エリアが空のまま「次へ」だけが出るのを避けるため。人間レビューで変えてよい）。「次へ」ボタンを押すたびに1つずつ出る。出し切ると「次へ」が消え、手札と「続きは準備中です。」（手札が空のとき）が出る。出し切るまで手札は出さない
  - 送り位置は `ConversationBeat` の `useState`（UI の状態）。親の `Playthrough` が `<ConversationBeat key={beat.id} …>` で描くので、ビートが変わるたびに部品ごと作り直されて最初に戻る。送り位置の `useState` を `key` を付ける側（親）に置かない（親の状態は `key` で戻らない）
  - 会話エリアは `role="log"`（新しい台詞が読み上げられる）。台詞の行の `key` は本文でなく位置にする
  - 新しい台詞が出たら、会話エリアを下までスクロールする。`scrollIntoView` は jsdom に無いので使わず、会話エリアの要素の `scrollTop = scrollHeight` にする（T4 の最初に、jsdom で `scrollTop` の代入を確かめられるかを確かめ、確かめられなければ確かめを E2E（実ブラウザ）に移す）
  - 上の NPC カードは、そのビートで直近に出た台詞の話し手を出す。純粋関数 `latestSpeaker(lines, revealed)`（`conversation.ts`。D5）で求める
- **D4 自分の台詞**：`cardSchema` に `say`（省略できる文字列）を足す。`{characterName}` は表示のときに置き換える（`renderText`）
- **D5 プレイログ（`PlayState.log`。仮の形）と会話の履歴**
  - `playStateSchema`：`beatId`（P4 の `sceneId` を置き換える）・`characterName`・`log`。`startPlay` は `start` のビート・名前 null・`log` は `[]`
  - `logEntrySchema`：`beatId`・`speaker`（NPC の id・`'player'`（定数 `PLAYER_SPEAKER`）・`null`（地の文））・`text`。`text` は `{characterName}` を置き換える前の形で持ち、表示のたびに置き換える（名前が決まった後も食い違わない）
  - `playCard` が、成功したときだけ、出したカードがあるビートの内容をログの末尾に足す：紙面のビートは各段落（`speaker: null`）、会話のビートは各行（`speaker` は NPC の id）。続けて、カードに `say` があれば自分の台詞（`speaker: 'player'`）を足す。`beatId` は出す前のビートの id。断った場合は `state` ごと返さないので、ログは増えない。入力の `state` は書き換えず、新しい `state`（新しい `log` の配列）を返す（P4 と同じ）
  - ログに入るのは「出し切った台詞」だけ（手札が出るのは出し切った後なので、途中までの台詞をドメインは知らない）。いま遊んでいるビートの台詞は、画面が送り位置まで描く
  - `packages/domain/src/scenario/conversation.ts`（会話の見せ方に関わる純粋関数）
    - `conversationHistory(scenario, state)`：会話エリアに出す履歴を返す。ログの末尾から、`beatId` が今のビートと同じシーンに属する行が続く間だけを遡り、そのうち会話のビートの行（NPC の台詞と、会話のビートで出したカードの自分の台詞）を返す。紙面のビートの行は返さないが、遡りは止めない。別のシーンの行に当たったら止める。境界を表すフィールドは持たない（`beatId` からシナリオを引けば決まる）
    - `latestSpeaker(lines, revealed)`：出した台詞（先頭から `revealed` 個）の最後の話し手の NPC の id。`revealed` が1未満・行数より大きいときは例外
  - 紙面のビートで出したカードの `say` は、紙面のビートの行なので、会話の履歴に出ない（今のデータの「受付へ進む」には `say` が無いので当たらない）。仕様の文は「会話のビートで出したカードの自分の台詞」とする（D8）
  - `renderText` の第2引数は `Pick<PlayState, 'characterName'>` に狭める（`PlayState` に `log` を足しても `text.test.ts` の入力が型エラーにならない）
  - イベントの列（core-loop）を作るときに、このログは置き換える。`docs/open-questions.md` の「遊んだことの持ち方」に、未決の中身として「会話の履歴を置く入れ物が、仮の形で `PlayState.log` にある。イベントの列に置き換えるときの形」を書く。実装の状態の記述は論点に置かず、コードの `log` のコメントと `docs/architecture/known-issues.md` に「仮」を書く
- **D6 画面の構成**（`pages/pl/exam/ui/`）
  - `ExamPage` は `adventurerExam` を読んで `Playthrough` に `scenario` として渡すだけにする。`Playthrough`（`PlayState`・名前を書くカード・断られた理由を持つ）は `scenario` を props で受け取る。画面のテストは `Playthrough` を、テスト用のシナリオ（`apps/web/src/test/screenScenario.ts`。`scenarioSchema.parse` を通す。`vi.mock` でデータのモジュールを差し替えない）で直接描く。ルート経由の描画（`renderAt`）は実データだけ
  - h1 は今のビートが属するシーンの題（どのビートでも h1 はちょうど1つ。同じシーンの中では変わらない）
  - 紙面のビート（`PaperBeat`）：今の紙面の画面のまま。段落の `key` は本文でなく位置にする
  - 会話のビート（`ConversationBeat`）：
    - 上：`NpcCard`（絵・名前・肩書の横長の帯。D2 のひとことを小さく添える）
    - 中：会話エリア。履歴（`conversationHistory`）の後に、今のビートの出た台詞を並べる。NPC の台詞は左、自分の台詞は右の吹き出し。残りの高さを占め、新しい行へ自動でスクロールする
    - 下：自分のカード（`PcCard`。名前か「（まだ名乗っていない）」と共通のシルエット）と手札。幅が狭いときは、自分のカードを手札の上の小さな帯にする
  - 名前の入力欄（`NameForm`）：会話エリアと手札の間に、今の登録用紙をそのまま出す。選んだときに記入欄へフォーカスを移す今の動きも残す
  - 提案の「準備中（仮）」：紙面・会話のどちらでも手札の隣。台詞を読んでいる間も出し続ける（押せない仮の表示。読んでいる間に本物の提案ができるかは、提案の保存の要望で決める）
  - 見た目のトークンは P4 のデザインシステムのもの（`apps/web/src/app/styles/tokens.css`）。吹き出し・会話エリア・NPC の帯・自分のカードの役割は `docs/architecture/web-app.md`「デザインシステム」に足す
- **D7 シナリオの中身**（`adventurer-exam.json`。組み替えだけ）
  - `npcs`：ミルダ（`milda`。`name` は「ミルダ」、`title` は「試験官」、`description` は「ギルドの登録を受け持つ女性」、絵は `icon`）

E2E（`apps/web/e2e/usecases/pl-1-play-card.test.ts`、タグ `@PL-1`。ステップ名は use-cases.md の表の `PL-1` のまま。待つ要素は、移った先のビートにしか無い台詞・段落）

25. `page.goto('/')` は最初の1回だけ。ホームのリンクから入口のビートへ（h1「ギルドの受付」と入口の段落を待つ）、「受付へ進む」で会話のビートへ（受付の最初の台詞と NPC カードを待つ）。ステップ「PL-1 名乗るを出す」で、「次へ」を押す前は台詞が1つ・「名乗る」が無い、1回押すと2つ、最後まで押すと「次へ」が消えて「名乗る」が出ることを確かめてから、名乗る → 名前を書いて確定 → `exam-begins` の台詞（名前入り）を待つ。自分の台詞が会話エリアに出ていることを確かめる。最後に同じステップの中で、コンソールの誤りが無いことと `alert` が0件であることを確かめる
