# 会話の画面

- 要望：[NPC と会話する場面を、会話の画面で遊べる](../backlog/conversation-mode.md)（同じ人間の要望から、メモは別の要望 [play-log-notes](../backlog/play-log-notes.md) に分けた）
- 状態：手順4〜5（実装とテスト）が済んだ（domain 75・web 28・E2E 3 通過、mutate-check 13 件すべて落ちる確認、docs:build 通過）。次は手順6（実装の AI レビュー、3観点並列）

## 1. 概要

試験の受付で、ミルダと話すところを「会話の画面」で遊べるようにする。画面は上に NPC のカード（絵・名前・肩書）、真ん中にチャットのような会話、下に自分のキャラクターのカードと手札を並べる。会話は台詞を1つずつタップして読み進め、読み終えると手札が出る。手札を出すと自分の台詞も会話に足される。ギルドの扉を開けるところは今の紙面のまま。

そのために、シナリオの形を「シーン（場面）の中にビート（プレイヤーが1回選ぶまでの一区切り）が並ぶ」に組み直し、ビートに「紙面」と「会話」の2つの見せ方、NPC、台詞の行、絵（アイコンか画像）、カードの自分の台詞を足す。遊んだことの並び（プレイログ）を `PlayState` に仮の形で持たせる。

## 3. 詳細設計

### 決めたこと

- **D1 シーンとビート**（`packages/domain/src/scenario/model.ts`）
  - `sceneSchema`：`id`・`title`・`beats`（ビートの配列。1つ以上）
  - `beatSchema` は `layout` で分ける `z.discriminatedUnion`：
    - `layout: 'paper'`：`id`・`text`（段落の配列。P4 の `text`）・`hand`
    - `layout: 'conversation'`：`id`・`lines`（台詞の行の配列。1行以上。各行は `speaker`（NPC の id）と `text`）・`hand`
  - P4 の `Scene`（題・段落・手札を持つもの）は、題をシーンに残し、段落と手札をビートへ移す。`layout` は省略できない（既定値を持たない）
  - `scenarioSchema`：`id`・`title`・`start`（ビートの id）・`npcs`・`scenes`。`superRefine` で止めるもの：ビートの id の重複（同じシーンの中でも、別のシーンどうしでも。シナリオ全体で一意）、シーンの id の重複、`start` とカードの `next` が無いビートを指す、同じ手札の中のカードの id の重複（P4 から）、NPC の id の重複・`player`、`speaker` が無い NPC を指す。ビートの id とシーンの id が同じ文字列でも通す（別の名前空間）。誤りの `path` は場所を指す（`scenes.0.beats.1.lines.0.speaker` など）
  - オブジェクトのスキーマ（シナリオ・シーン・ビート・台詞の行・カード・NPC・絵）はすべて `z.strictObject` にする。余分なキー（`layout: 'paper'` に `lines` を入れる、`say` の綴り違いなど）を黙って捨てずに断る
  - zod 4.6.7 の挙動（node_modules で確かめた）：`discriminatedUnion` は判別の値が合わないと `path` に判別のキーを付ける（`layout` が無い・未知なら `scenes.0.beats.0.layout`）。形の誤りが1件でもあると `superRefine` は走らない（形の誤りと参照の誤りを同時には報告しない）
  - `locateBeat(scenario, beatId)`（`transition.ts`）：ビートと、それが属するシーンを返す（無ければ `undefined`）。`playCard`・`conversationHistory`・画面が使う。`transition.ts` の先頭のコメントは「ビートの進み方と、ビートの引き当て」に直す
- **D2 NPC と絵**
  - `npcSchema`：`id`（1文字以上）・`name`・`title`（肩書）・`description`（ひとこと。`NpcCard` が名前・肩書の下に小さく出す。幅が狭いときは隠す）・`portrait`
  - `portraitSchema` は `{ type: 'icon', name }` か `{ type: 'image', src }`（`name`・`src` は1文字以上）。ドメインは React を知らないので `name` は文字列のまま。会話の行の `speaker` に `player` は書けない（`npcs` に無いので参照の切れになる。自分の台詞は `say` だけで表す）
  - 画面側（`apps/web/src/pages/pl/exam/ui/`）に `Portrait` を作る。`type: 'icon'` は `portraitIcons.ts`（`react-icons/gi` から使うものだけを import した、名前 → 部品のオブジェクトの表。`export { … } from` は `noBarrelFile`・`noReExportAll` に当たるので使わない）から引き、`type: 'image'` は `<img src alt={NPC の名前}>`。登録表に無い名前は `Portrait` が例外にする（シナリオの誤りを黙って隠さない。P4 の「シーンが見つからない」と同じ）
  - 自分のカードの絵は、画面側の定数（共通のシルエットのアイコン）。ドメインのデータには持たせない
  - `react-icons` を `apps/web` の依存に足す。版は実装のセッションで、リリースから2週間以上経ったものを確かめて決める。アイコンの名前が実在することは `web:typecheck` が確かめる。`biome.json` の `noRestrictedImports` は `react-icons` を止めないことを確かめた。`gi` は全アイコンが1つのモジュールにあるので、導入のときにビルド（`pnpm build:pages`）で、使う名前だけが入っていること（ビルドの大きさ）を確かめる
- **D3 台詞の送り（画面の状態）**
  - 会話のビートに入ると、最初の台詞が出ている状態から始める（AI の既定。会話エリアが空のまま「次へ」だけが出るのを避けるため。人間レビューで変えてよい）。「次へ」ボタンを押すたびに1つずつ出る。出し切ると「次へ」が消え、手札と「続きは準備中です。」（手札が空のとき）が出る。出し切るまで手札は出さない
  - 送り位置は `ConversationBeat` の `useState`（UI の状態）。親の `Playthrough` が `<ConversationBeat key={beat.id} …>` で描くので、ビートが変わるたびに部品ごと作り直されて最初に戻る。送り位置の `useState` を `key` を付ける側（親）に置かない（親の状態は `key` で戻らない）
  - 会話エリアは `role="log"`（新しい台詞が読み上げられる）。台詞の行の `key` は本文でなく位置にする
  - 新しい台詞が出たら（入った時と「次へ」のたび）、会話エリアの要素の `scrollTop` に `scrollHeight` を代入して下までスクロールする（`scrollIntoView` は jsdom に無い）。jsdom の `scrollHeight` は常に 0 なので（30.1.3 の `Element-impl.js` で確かめた）、テストでは `scrollHeight` を `Object.defineProperty` で固定値にし、`scrollTop` のセッターを `vi.fn` にして、その値で呼ばれることを確かめる（テスト23）
  - 上の NPC カードは、そのビートで直近に出た台詞の話し手を出す。純粋関数 `latestSpeaker(lines, revealed)` で求める。送り位置は画面の状態で、使うのはこのページだけなので、スライスの `pages/pl/exam/lib/latestSpeaker.ts` に置く（architecture.md「迷ったらこの順で問う」）。`revealed` が1未満・行数より大きいときは例外
- **D4 自分の台詞**：`cardSchema` に `say`（省略できる文字列）を足す。`{characterName}` は表示のときに置き換える（`renderText`）
- **D5 プレイログ（`PlayState.log`。仮の形）と会話の履歴**
  - `playStateSchema`：`beatId`（P4 の `sceneId` を置き換える）・`characterName`・`log`。`startPlay` は `start` のビート・名前 null・`log` は `[]`
  - `logEntrySchema`：`beatId`・`speaker`（NPC の id・`'player'`（定数 `PLAYER_SPEAKER`）・`null`（地の文））・`text`。`text` は `{characterName}` を置き換える前の形で持ち、表示のたびに置き換える（名前が決まった後も食い違わない）
  - `playCard` が、成功したときだけ、出したカードがあるビートの内容をログの末尾に足す：紙面のビートは各段落（`speaker: null`）、会話のビートは各行（`speaker` は NPC の id）。続けて、カードに `say` があれば自分の台詞（`speaker: 'player'`）を足す。`beatId` は出す前のビートの id。断った場合は `state` ごと返さないので、ログは増えない。入力の `state` は書き換えず、新しい `state`（新しい `log` の配列）を返す（P4 と同じ）
  - ログに入るのは「出し切った台詞」だけ（手札が出るのは出し切った後なので、途中までの台詞をドメインは知らない）。いま遊んでいるビートの台詞は、画面が送り位置まで描く
  - `conversationHistory(scenario, state)`（`packages/domain/src/scenario/conversation.ts`）：会話エリアに出す履歴を返す。ログの末尾から、`beatId` が今のビートと同じシーンに属する行が続く間だけを遡り、そのうち会話のビートの行（NPC の台詞と、会話のビートで出したカードの自分の台詞）を返す。紙面のビートの行は返さないが、遡りは止めない。別のシーンの行に当たったら止める。境界を表すフィールドは持たない（`beatId` からシナリオを引けば決まる）。ログの行の `beatId` がシナリオに無いときは例外（ログは `playCard` だけが作るので起きない。起きたら隠さない）。仕様の節「ビートの見せ方」に書く決まり（D8）を、この関数が持つ
  - 紙面のビートで出したカードの `say` は、紙面のビートの行なので、会話の履歴に出ない（今のデータの「受付へ進む」には `say` が無いので当たらない）。仕様の文は「会話のビートで出したカードの自分の台詞」とする（D8）
  - `renderText` の第2引数は `Pick<PlayState, 'characterName'>` に狭める（`PlayState` に `log` を足しても `text.test.ts` の入力が型エラーにならない）
  - イベントの列（core-loop）を作るときに、このログは置き換える。`docs/open-questions.md` の「遊んだことの持ち方」に、未決の中身として書く（D8）。実装の状態の記述は論点・用語集に置かず、コードの `log` のコメントと `docs/architecture/known-issues.md` に「仮」を書く
- **D6 画面の構成**（`pages/pl/exam/ui/`）
  - `ExamPage` は `adventurerExam` を読んで `Playthrough` に `scenario` として渡すだけにする。`Playthrough`（`PlayState`・名前を書くカード・断られた理由と、カードを出す `play` を持つ）は `scenario` を props で受け取る。画面のテストは `Playthrough` を、テスト用のシナリオ（`apps/web/src/test/screenScenario.ts`。`scenarioSchema.parse` を通す。`vi.mock` でデータのモジュールを差し替えない）で直接描く。ルート経由の描画（`renderAt`）は実データだけ
  - h1 は今のビートが属するシーンの題（`Playthrough` が描く。どのビートでも h1 はちょうど1つ。同じシーンの中では変わらない）
  - 手札のエリア（`HandZone`）を1つの部品にして、紙面・会話の両方のビートから使う（書き写さない）。描くもの：手札のカード・「続きは準備中です。」（手札が空のとき）・提案の「準備中（仮）」・名前の入力欄（`NameForm`。名前を書くカードを選んだとき、手札の上に）。props は手札・選んでいるカード・断られた理由・カードを押したとき・名前を確定したとき。`Playthrough` から各ビートへ、その props をそのまま渡す
  - 紙面のビート（`PaperBeat`）：今の紙面の画面のまま（段落と `HandZone`）。段落の `key` は本文でなく位置にする。区画のラベルは「地の文」（P4 の「シーン」から変える）
  - 会話のビート（`ConversationBeat`。受け取るもの：ビート・NPC の表・履歴（`conversationHistory` の結果）・名前・`HandZone` の props）：
    - 上：`NpcCard`（絵・名前・肩書の横長の帯。D2 のひとことを小さく添える）
